# Verifying the Relevance of Cited References in Scientific Articles

Reproducibility package for the article *Verifying the Relevance of Cited References in Scientific Articles: A Hybrid Approach Combining Knowledge Graphs and Generative AI* (Youssef El Yaakoubi).

Every number, table and figure in the article is regenerated by the scripts in `analysis/` from the artefacts stored here: the persisted knowledge graph, the LightRAG key–value stores, the LLM response cache, the server log and the pilot results. Nothing is typed by hand.

## Layout

| Path | Content |
|---|---|
| `Verifying_the_Relevance_…_ieee.tex`, `references.bib` | LaTeX source of the article (IEEEtran). `latexmk -pdf` builds it. |
| `data/numbers_*.tex` | Macros holding every number quoted in the text (generated). |
| `tables/*.tex`, `figures/*` | Tables I–XII and Figs. 3–8 (generated). |
| `data/*.json`, `data/*.csv` | Machine-readable results: graph statistics, schema audit, label coverage, pilot results and summary, the annotation sheet (one row per pilot pair, human columns empty). |
| `analysis/*.py` | The analysis scripts (see below). |
| `analysis/rag_storage_pilot/` | Frozen copy of the LightRAG working directory after ingestion: GraphML graph (12,309 nodes, 20,537 edges), KV stores (documents, chunks, entities, relations, document status) and the LLM response cache (1,368 responses, with prompts). The pilot ran in process on this copy. |
| `analysis/pilot.log`, `analysis/pilot_run.out` | Logs of the pilot run. |
| `LightRAG/` | Working tree of the LightRAG fork used for ingestion and querying (version 1.5.8 plus the changes below), without its git history, virtual environment, web UI dependencies and corpus PDFs. |
| `LightRAG/.env.article` | The runtime configuration keys read for Table III. The server `.env` itself is not published. |
| `LightRAG/lightrag.log` | Server log of the ingestion sessions (Tables IV and V). |
| `LightRAG-fork/` | How the fork differs from upstream `HKUDS/LightRAG`: base commit, three patches and the uncommitted diff. |
| `publish.sh` | rsync of the author's working folder into this repository (lists what is excluded). |

## What the fork adds to LightRAG

- `lightrag/llm/claude_agent_sdk.py`: a `claude_agent_sdk` LLM binding with a configurable effort setting (patch 0001).
- `prompts/samples/scientific_citation.yml`: the citation-oriented extraction profile (nine entity types, fourteen controlled relations) and `examples/scientific_citation_kg.py` with the strict schema validator and the graph script (patch 0003).
- `KG_ENTITY_LOOKUP_METHOD=LABEL`: name-based entity lookup at query time when no vector index exists, and the chunk-selection fallback fix (`lightrag/operate.py`, `lightrag/lightrag.py`, tests) — in `LightRAG-fork/uncommitted.diff` and already applied in `LightRAG/`.
- `NoopVectorDBStorage` hardening so that ingestion and querying run without any embedding (`lightrag/kg/noop_vector_db_impl.py`).

## Regenerating the article's numbers

Requirements: Python 3.12+ with `networkx`, `numpy`, `matplotlib` (and the fork's dependencies for the pilot: `pip install -e LightRAG`).

```bash
cd analysis
python graph_stats.py        # Tables II–VIII, X; data/numbers_stats.tex; data/graph_stats.json
python audit_llm_cache.py    # Table IX; data/numbers_audit.tex; data/schema_audit.json
python label_coverage.py     # Table XI; data/numbers_label.tex; data/label_coverage.json
python figures.py            # Figs. 3–6, 8 (figures/*.pdf, *.png)
python pilot_verification.py --summarize-only   # Table XII, data/numbers_pilot.tex, data/annotation_sheet.csv (from data/pilot_results.json, no LLM call)
```

`common.py` locates the storage automatically: it uses `LightRAG/rag_storage/` when a live server directory exists, otherwise `analysis/rag_storage_pilot/`. Re-running the pilot with new LLM calls (`python pilot_verification.py`) requires the Claude Agent SDK binding and a Claude subscription; the stored `data/pilot_llm_cache.json` makes the recorded run replayable.

Then build the article:

```bash
latexmk -pdf Verifying_the_Relevance_of_Cited_References_in_Scientific_Articles__A_Hybrid_Approach_Combining_Knowledge_Graphs_and_Generative_AI_ieee.tex
```

## Corpus

The 35 processed documents are listed in Table II and `data/corpus.csv`. Their text is embedded in the KV stores and in the prompts of the LLM response cache; the PDF files themselves are not redistributed.
